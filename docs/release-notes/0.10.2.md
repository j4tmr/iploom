# IPloom Studio 0.10.2

This patch makes the desktop main process follow the in-app language while the app is running. Switching between 中文 and English now re-derives native dialogs, save and close prompts, IPC validation errors and AI failure copy immediately, instead of leaving them in the language that was active at launch. Workspaces stay on schema v7 and no migration runs on upgrade.

## Highlights

- **Main-process copy follows the language switch** — native dialogs, save/close prompts, IPC validation messages and AI failures re-derive from the workspace locale on load, save, snapshot restore, demo reset and startup, so they match the rest of the interface without a restart.
- **Locale values are validated** — a locale arriving over IPC is checked against the supported set and falls back to the OS locale, so an unsupported value can never move the interface into an unknown language.
- **The workspace store re-derives its copy** — the store no longer keeps the startup catalog; it adopts the new one together with the rest of the main process.
- **The wiring is guarded** — a new source-level test fails the suite if any place that adopts a workspace stops re-deriving the catalog, because the Electron entry point cannot be loaded by the Bun test process itself.

## Compatibility

- Workspace schema remains **v7**; existing workspaces open without migration.
- English copy stays unchanged, and the MCP server continues to emit English messages regardless of the UI locale.
- No new permissions, network calls or telemetry.
