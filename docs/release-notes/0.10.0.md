# IPloom Studio 0.10.0

A focused minor release that finishes the paging story for `get_workflow_result`: the first pre-change snapshot now pages with the same per-language windows as the current result, so a client revising a large AI output no longer re-downloads up to 200,000 characters of old text on every windowed call. Workspaces do not change: schema stays at v7 and no migration runs on upgrade.

## Highlights

- **The snapshot pages too** — `get_workflow_result`'s window arguments (`offset` / `result_offsets` / `max_chars`) previously applied only to the current `result`; `previous_result` was still returned in full on every windowed call. The same surrogate-safe window now applies to both texts: each language of the snapshot becomes the same `{ text, offset, total_chars, next_offset, truncated }` shape the result already uses.
- **Lockstep reassembly for both texts** — the snapshot shares the same offsets as the result, so a language past its end returns empty text with `next_offset: null` and the same sequence of calls reassembles both the current text and the snapshot exactly. Each language continues from its own `next_offset` via `result_offsets`.
- **Default responses unchanged** — without any window argument the tool still returns both texts in full, byte-for-byte the same as 0.9.0, and a task without a snapshot keeps `previous_result: null`, so existing client integrations need no changes.
- **19 tools** — the local MCP server registers 19 tools: thirteen read-only, five workspace writes (`create_standard`, `update_standard`, `create_timeline_event`, `update_timeline_event`, `save_workflow_result`) and one ArcReel export.

## Compatibility

- Workspace schema remains **v7**; existing workspaces open without migration.
- Windowed `previous_result` is the only response-shape change, and it only affects calls that pass `offset` / `result_offsets` / `max_chars`; default (unwindowed) responses are unchanged. Tool descriptions and `docs/mcp.md` document the shape.
- Existing client configurations keep working unchanged.
- Node.js 24 and Bun 1.4.2 remain the development prerequisites.
