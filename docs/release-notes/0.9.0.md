# IPloom Studio 0.9.0

A focused minor release that closes the gap between what MCP clients see and what the in-app production run sees: `get_workflow_brief` can now include the outputs of every approved ancestor task, so an external agent executing a production task works from the same dependency results the desktop prompt does. Workspaces do not change: schema stays at v7 and no migration runs on upgrade.

## Highlights

- **Approved dependency outputs on demand** — `get_workflow_brief` accepts an optional `include_approved_outputs` flag (default `false`). When set, the brief gains an "APPROVED DEPENDENCY OUTPUTS" section listing each done ancestor task with its production stage label, localized title and current output, in the same dependency order the in-app production prompt uses.
- **Same budget rule as the desktop prompt** — when the enriched brief would exceed the requested `max_chars` window, each output is clipped to an equal share of the remaining budget with a `[…truncated]` marker, mirroring the in-app prompt's issue #21 semantics; a window smaller than the bare brief collapses outputs to a "—" placeholder instead of flooding the response.
- **Default responses unchanged** — without the flag the tool returns byte-for-byte the same brief as 0.8.0, so existing client integrations need no changes.
- **19 tools** — the local MCP server registers 19 tools: thirteen read-only, five workspace writes (`create_standard`, `update_standard`, `create_timeline_event`, `update_timeline_event`, `save_workflow_result`) and one ArcReel export.

## Compatibility

- Workspace schema remains **v7**; existing workspaces open without migration.
- The new flag is additive and optional; tool descriptions and `docs/mcp.md` document the shape. Default responses are unchanged.
- Existing client configurations keep working unchanged.
- Node.js 24 and Bun 1.4.2 remain the development prerequisites.
