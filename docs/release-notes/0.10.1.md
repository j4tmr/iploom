# IPloom Studio 0.10.1

A fix-only release that finishes Chinese localization in the desktop main process. The renderer was already bilingual, but native dialogs, IPC errors and AI failures raised by the main process stayed English under zh-CN; 0.10.1 routes every one of them through the injected message catalog. English copy is byte-identical to 0.10.0, the workspace schema stays at v7, and no migration runs on upgrade.

## Highlights

- **Native dialogs are bilingual** — the six main-process dialogs (reload canceled, close-failure choices, missing recovery copy, recovery copy saved, recovery copy failure, renderer crash) build their title, message, detail and buttons from the locale catalog, keeping identical button ids, default and cancel indexes in both languages.
- **AI errors read as one clean sentence** — canceled requests, first-byte and idle timeouts, HTTP status hints, and invalid configuration or request input are localized in the main process; Zod validation details are collapsed into a single actionable message instead of leaking JSON.
- **Save and export errors localized** — unsafe export paths, stale-revision refusals, unreadable-workspace quarantine messages and file-guard errors come from the same catalog; the MCP server and every default constructor keep the pre-localization English strings byte-identical.
- **The guard covers the Electron tree** — the localization guard test now scans `apps/studio/electron` as well as the renderer trees, so inline `locale === …` copy branching in the main process fails the suite.

## Compatibility

- Workspace schema remains **v7**; existing workspaces open without migration.
- English copy is byte-identical to 0.10.0; the MCP error contract and existing message-matching tests are unchanged.
- The MCP server keeps emitting English messages regardless of UI locale.
- Node.js 24 and Bun 1.4.2 remain the development prerequisites.
