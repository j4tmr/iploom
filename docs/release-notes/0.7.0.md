# IPloom Studio 0.7.0

A focused minor release that closes the AI authoring loop over MCP: local clients can now return the result they produced for a workflow task. Workspaces do not change: schema stays at v7 and no migration runs on upgrade.

## Highlights

- **Workflow results over MCP** — the new `save_workflow_result` tool writes Chinese and/or English result text to an existing workflow task. Omit a language to keep its stored text; an explicit empty string clears one language only while the other still has non-whitespace text. A patch with neither language, or with both empty, returns `invalid_arguments`.
- **The app's review flow, unchanged** — `queued` and `active` tasks move to `review` when a result arrives, and `review` tasks can be revised. A `done` task is rejected until the author reopens it in the app, so an MCP client cannot silently replace an approved result.
- **History and downstream signals** — the first pre-change text is snapshotted as `previous_result_chars` (the first snapshot wins), and dependents already marked done are flagged `result_superseded` when the result they consumed changes. The producer's own flag is cleared.
- **Bounded responses** — the tool returns the same task summary as the read tools: ids, status, brief and deliverable sizes, a 200-character excerpt, previous-result sizes and timestamps. It never echoes the full result text.
- **18 tools** — the local MCP server now registers 18 tools: twelve read-only, five writes (`create_standard`, `update_standard`, `create_timeline_event`, `update_timeline_event`, `save_workflow_result`) and one ArcReel export.

## Compatibility

- Workspace schema remains **v7**; existing workspaces open without migration.
- Both result languages are capped at 200,000 characters, matching the workspace schema and the in-app editor.
- The tool is additive, so existing client configurations keep working unchanged.
- Node.js 24 and Bun 1.4.2 remain the development prerequisites.
