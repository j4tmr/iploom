# IPloom Studio 0.11.0

A minor release that exposes story objects through the local MCP world tool and adds the structured world-rule foundation to the workspace schema. Existing v7 workspaces migrate automatically to v8; no data is removed and no manual migration is required.

## Highlights

- **Story objects are enumerable through MCP** — `get_story_world` now returns a paged `objects` collection with `id`, `world_id`, `name`, `category`, `summary`, `visual_prompt`, `source_notes`, `created_at` and `updated_at`. It also reports `stats.objects`, accepts `offsets.objects`, and can be walked with `next_offset` without a search keyword. The server still registers 19 tools: thirteen read-only, five workspace writes and one export.
- **Shared response budgets stay bounded** — long values in the world record and its story-object views are clipped by default and named in `truncated_fields`. Pass `include_details: true` for full values. A dense seven-collection world now has a regression test guarding the shared paging budget. The roughly 50 KB value is a paging budget, not a universal response cap: explicit large-payload options can still exceed it.
- **A structured rule layer enters the workspace model** — schema v8 adds universe-scoped rule systems with ordered tiers and typed attributes, plus ability and item-stat templates. Active, in-scope rule systems and their linked templates are serialized as data in production prompts and workflow briefs. The declarative skill contract and bundled `world.foundation` skill draft standards and rule systems for author review; registration appends only the author's explicit selection to a workspace clone and revalidates it.
- **The migration is additive** — v7→v8 adds empty `ruleSystems`, `abilityTemplates` and `itemStatTemplates`, bumps `revision`, and leaves existing prose standards and content unchanged.

## Compatibility

- This is a **MINOR** release under the project's version rules: additive schema fields and automatic migrations are backwards-compatible capabilities.
- Existing MCP client configurations keep working with the same 19 tool names and access levels. Default `get_story_world` responses are not byte-for-byte identical to 0.10.2: they add `objects` and `stats.objects`, may clip long world `name`, `tagline` and `summary`, and report those paths in `truncated_fields`. Clients that require full long text should pass `include_details: true`; clients that require an exact response shape should tolerate the new fields.
- Once a v8 workspace has been saved, 0.10.x and older builds cannot open it because they only accept schema v7. Keep an independent backup before downgrading. No database or production migration is involved.
- This slice adds the rule layer as core/library functionality: no structured-rule authoring UI, MCP rule tools, entity tier bindings, ArcReel export or consistency-check surface is shipped. [j4tmr/iploom#111](https://github.com/j4tmr/iploom/issues/111) and [j4tmr/iploom#112](https://github.com/j4tmr/iploom/issues/112) remain follow-ups. [j4tmr/iploom#113](https://github.com/j4tmr/iploom/issues/113) also remains open: task `standardRefs` are informational, while prompts resolve active standards at composition time rather than replaying a stored historical version.
- Node.js 24 and Bun 1.4.2 remain the development prerequisites.
