# IPloom Studio 0.8.0

A focused minor release that makes MCP result reads cheaper to sample: the new per-language windowing on `get_workflow_result` lets a client inspect a slice of the bilingual result without paying for up to 200,000 characters per language. Workspaces do not change: schema stays at v7 and no migration runs on upgrade.

## Highlights

- **Per-language result windows** — `get_workflow_result` accepts an optional `offset`, a strict `result_offsets` object (`{ "zh": 4000, "en": 4002 }`) and a `max_chars` cap (default 4,000 when windowing). Each language then becomes a surrogate-safe window: `text`, `total_chars`, `next_offset` and `truncated`, continuing per language exactly like `get_standard`'s body windows.
- **Full reads unchanged** — without any window argument the tool still returns the complete bilingual result and the first pre-change snapshot, so existing revision workflows keep the exact response shape they had in 0.7.0.
- **Sampling before review** — a client can sanity-check a produced result before calling `save_workflow_result` at a fraction of the payload, and follow `next_offset` to `null` when it does want the whole text.
- **19 tools** — the local MCP server registers 19 tools: thirteen read-only, five workspace writes (`create_standard`, `update_standard`, `create_timeline_event`, `update_timeline_event`, `save_workflow_result`) and one ArcReel export.

## Compatibility

- Workspace schema remains **v7**; existing workspaces open without migration.
- The windowing arguments are additive and optional; tool descriptions and `docs/mcp.md` document the shape. Each language stays bounded by the stored 200,000-character cap, and windows never split a surrogate pair.
- Existing client configurations keep working unchanged.
- Node.js 24 and Bun 1.4.2 remain the development prerequisites.
